# ADR-0004: Допуск первичного луча во float32 на GPU: κ = 3e-3, α = 0.1/ℓ_s

**Контекст.** DD-004 п. 2 заранее зафиксировал правило: повторить на GPU бенчмарк первичных лучей и взять
наименьшую стоимость при p99 ошибки направления ≤ 0.05 θ_pix. Пользователь разрешил поднять κ по измерению
(ревью DD-004).

**Измерение.** `results/stage-3/2026-10-24_gpu_kappa_alpha/table.md`: 1080p, fov 90° (θ_pix ≈ 1.04e-3),
4096 случайных пикселей, GPU float32 против прототипа f64 (DOPRI5 tol 1e-12).

| α·ℓ_s | κ | Эллис p99, θ_pix | компактная p99, θ_pix | проходов (Эллис / компактная) |
|---|---|---|---|---|
| 0.1 | 1e-3 | 0.020 | 0.025 | 243 / 306 |
| 0.1 | **3e-3** | **0.040** | **0.047** | 180 / 229 |
| 0.1 | 1e-2 | 0.092 | 0.143 | 132 / 170 |
| 0 | 3e-3 | 0.041 | 0.059 | 180 / 229 |
| 1 | 3e-3 | 0.175 | 0.071 | 184 / 229 |

Пол округления float32 не достигнут: при κ = 3e-4 p99 = 0.011 / 0.0065 θ_pix.

**Решение.** На GPU κ = 3e-3 (tol = 3e-3·θ_pix), α = 0.1/ℓ_s (ADR-0001 подтверждён во float32: α = 1/ℓ_s
хуже в 1.5–4 раза, α = 0 не проходит порог на компактной). Прототип (float64) по-прежнему с κ = 1e-3 (ADR-0002).

**Последствия.** Центральный проход режима A примерно на четверть дешевле, чем при κ = 1e-3 (180 против 243
проходов на Эллисе). Правило проверено для θ_pix 1080p. В 4K θ_pix вдвое меньше, и tol = 3e-3·θ_pix ≈ 1.6e-6 ближе
к полу float32, но всё ещё выше tol ≈ 3e-7 (κ = 3e-4 в 1080p), при котором пол не достигнут; отдельно в 4K не проверено.

**Статус.** Accepted, 2026-10-24.
