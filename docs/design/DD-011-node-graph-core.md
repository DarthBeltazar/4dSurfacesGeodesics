# DD-011: ядро нодовой системы сцен
Статус: **Review** (по правилам проекта ревью обязательно только для DD-004/DD-005; показан пользователю, т. к.
определяет, как пользователь строит сцены)
Этап: после 5 (самостоятельное приложение, [концепция](concept-standalone-nodes.md))        Дата: 2026-10-25

## Контекст и задача
Сцена сейчас — плоский JSON (DD-008): одно многообразие из 8 зашитых видов (`scenes.slang`), до 32 объектов трёх
видов (ball4, тор в листе, полупространство), три материала. Пользователь хочет строить сцены графом нод, как в
Houdini: многообразия и объекты из библиотеки и из выражений, процедурные текстуры, позже — подграфы. Решения
пользователя и пробы — в [концепции](concept-standalone-nodes.md):

- три контекста графа с типизированными портами: многообразие f, объекты g, текстуры/материалы;
- ноды выражений (softmin, exp, …) и библиотечные ноды; подграфы позже, но формат сразу под них;
- параметры (ползунки) — мгновенно; структурная правка — сразу **предпросмотр на интерпретаторе** (55 мс в 720p,
  17 мс в 360p — [probe_preview](../../results/stage-5/2026-10-25_probe_preview)), нативная компиляция в фоне (~2 с —
  [standalone_startup](../../results/stage-5/2026-10-25_standalone_startup)); интерпретатор для полного рендера
  отклонён (15–24× медленнее);
- всё в C++ (DD-010), Python — эталон в тестах.

Этот DD — **ядро**: формат графа, язык выражений, библиотека нод, метаданные, кодген, слоты параметров, байткод и
ядро предпросмотра, эталон в Python, миграция сцен. Интерфейс (вьюпорт и режимы «Предпросмотр/Рендер», наложения,
компоновка с панелями, редактор нод) — **DD-012**; поставка zip — **DD-013** (в концепции они были DD-012 и нет).

## Цели / не-цели
**Цели:**
- формат сцены `.g4d` (JSON, version 2) с графами нод; старые `scenes/*.json` (version 1) открываются миграцией;
- язык выражений с контекстами (гладкие функции в геометрии; любые — в текстурах) и одна реализация его разбора в
  C++ (кодген, байткод, CPU-вычисление) плюс эталонная в Python (тесты);
- библиотека нод — данные (`nodes/*.json`): многообразия (8 нынешних видов точь-в-точь, листы и горловины как
  составные ноды), объекты и гладкая CSG, преобразования, материалы, текстуры, математика;
- метаданные, которые нужны интегратору и трассировщику (ℓ_s и α, `hcap`, плоские зоны и листы, выход режима A,
  ограничивающие сферы, константа Липшица), выводятся по графу, а не пишутся руками;
- параметры в слотах буфера: ползунок меняет кадр без перекомпиляции (в обоих путях — нативном и интерпретаторе);
- байткод и ядро предпросмотра: изменённый граф виден сразу, нативные шейдеры собираются в фоне;
- до DD-012 — временная панель «Параметры» (ползунки всех параметров графа) и перезагрузка `.g4d` при изменении
  файла (структурные правки — правкой файла).

**Не-цели:** редактор нод и новая компоновка окна (DD-012); подграфы (только формат под них); излучение по текстуре
(решение пользователя: не в v1); несколько многообразий в сцене; новые методы интегрирования; изменение режима A.

## Математика (черновики, в `docs/math.md` — при реализации, с тестами)
**M35 (черн.). Листы с горловинами.** База «два листа» `w = ±W` и N горловин (cᵢ, bᵢ, ρ₀ᵢ) с непересекающимися
шарами носителей |q − cᵢ| < ρ₀ᵢ:

  f = w² − W² + Σᵢ (W² − hᵢ(|q − cᵢ|)),   hᵢ(ρ) = W²·ψ((ρ − bᵢ)/(ρ₀ᵢ − bᵢ))  (M11).

Вне всех шаров слагаемые ≡ 0 → f = w² − W² (листы, кривизна 0); в шаре i f совпадает с M11 со сдвигом. При N = 2 и
равных b, ρ₀ — это M12 (тождественно, порядок операций другой). Плоские зоны: листы ±W, шары (cᵢ, ρ₀ᵢ);
`hcap(x) = max(minᵢ(|q − cᵢ| − ρ₀ᵢ), ¼·minᵢ bᵢ)`; ℓ_s = minᵢ bᵢ. Проверка: f, ∇f, H против M12 на точках (N = 2),
геодезические через каждую горловину против DOP853.

**M36 (черн.). Объекты: граница расстояния при CSG и преобразованиях.** Требование M26: g 1-липшицева и
g ≤ расстояния до {g = 0}. Сохраняют его:
- объединение `smin_k(a, b) = −k·ln(e^{−a/k} + e^{−b/k})` (M6): ≤ min(a, b), градиент — выпуклая комбинация → 1-липш.;
- пересечение `smax_k(a, b) − k·ln 2` (≤ max(a, b) — граница для пересечения), вычитание = пересечение с −b;
- жёсткие преобразования; равномерный масштаб s: s·g(p/s); неравномерный diag(dᵢ): min(dᵢ)·g(D⁻¹p) (константа
  Липшица ≤ 1, граница консервативна — шаг меньше).
Нода-выражение объекта объявляет константу Липшица L (по умолчанию 1); трассировщик делит g на L.
Проверка: на точках |∇g| ≤ 1 + ε и g ≤ расстояния (расстояние — бисекцией по лучу) для каждой ноды и комбинаций.

**M37 (черн.). Метаданные многообразия по графу.** Нода многообразия даёт (f, meta), meta = {ℓ_s; листы {wⱼ} или
«нет»; шары носителей {(cᵢ, ρᵢ)}; выход: плоский | Эллис | нет (компактное); `s_max`; признак «вид известен»}.
Правила: база задаёт листы и выход; горловины добавляют шары (проверка непересечения); сдвиг по xyz сдвигает шары,
по w — листы; поворот в плоскостях xyz — поворачивает центры; поворот, смешивающий w, и любая нода-выражение без
объявленных метаданных → «вид неизвестен»: шаг ограничен ℓ_s, плоских зон нет (NEE нет), выход — только объявленный.
Объявленные метаданные проверяются численно: vᵀHv ≈ 0 и f(q, w) ≈ f(q', w) вне шаров на выборке (иначе ошибка
загрузки с сообщением, как недопустимые параметры в DD-009).

## Предлагаемое решение
### 1. Формат `.g4d` (version 2)
```json
{ "format": "geo4d", "version": 2,
  "graphs": { "main": {
      "nodes": [ {"id": "base", "type": "mf.two_sheets", "params": {"W": 1.5}, "ui": {"pos": [0, 0]}},
                 {"id": "t1", "type": "mf.throat", "params": {"c": [-4, 0, 0], "b": 1.0, "rho0": 3.0}},
                 {"id": "ball", "type": "obj.ball4", "params": {"c": [0, -4.5, -2.7, 1.5], "r": 0.8}},
                 {"id": "red", "type": "mat.diffuse", "params": {"albedo": [0.8, 0.3, 0.2]}},
                 {"id": "o1", "type": "out.object", "params": {"name": "шар"}},
                 {"id": "scene", "type": "out.scene"} ],
      "links": [ {"from": "base.out", "to": "t1.base"}, {"from": "t1.out", "to": "scene.manifold"},
                 {"from": "ball.out", "to": "o1.shape"}, {"from": "red.out", "to": "o1.material"},
                 {"from": "o1.out", "to": "scene.objects"} ] } },
  "camera": {"x": [0, -11, 0.5, 1.5], "f": [0, 1, -0.12, 0], "up": [0, 0, 1, 0], "fov": 75},
  "settings": {"speed": 2.0, "env": "procedural"} }
```
- `graphs` — словарь с первого дня: подграф — ещё одна запись и нода `subgraph` с `"graph": "<имя>"` и вынесенными
  параметрами. Компилятор работает в два шага: развернуть граф (подграфы, массивы) → внутреннее представление.
- Вход-список (`scene.objects`) принимает несколько связей, порядок — по порядку в `links`.
- Миграция v1 → v2 (C++ и Python, одинаково): многообразие → нода своего вида (§3), каждый объект →
  `obj.*` + `mat.*` + `out.object`; `on_M` → нода `xf.on_M`. Тест: круговой обмен v1 → v2 → строки буфера и
  заголовок те же.

### 2. Язык выражений
- Числа, `x y z w` (точка в R⁴ в текущих координатах ноды), имена входов и параметров, `+ − * /`, унарный минус,
  `^` (целая степень), вызовы функций; в контексте текстуры ещё сравнения, `?:`, `&& ||`.
- Типы: скаляр, `vec3`/`vec4` (литералы, компоненты `.x…`, покомпонентные операции), цвет = `vec3` в текстурах.
- Функции геометрии (гладкие, через `IReal`): `sqrt` (с защитой нуля), `length(…)` (M6), `exp log sin cos tan cosh
  sinh tanh`, `pow(a, n)` с целым n, `smin(a, b, k)`, `smax(a, b, k)`, `sabs(a, k)`, `psi(u)` (M11), `clamp_s`
  (гладкая). Запрещены (ошибка разбора с указанием места): `abs min max floor fract mod step` и сравнения.
- Функции текстур: всё перечисленное плюс `abs min max floor fract mod step smoothstep mix clamp`, сравнения,
  шум `noise(p)`, `fbm(p, octaves, lac, gain)`, `voronoi(p)` (встроенные — одна инструкция байткода).
- Разбор — один в C++ (`expr.{hpp,cpp}`: лексер, рекурсивный спуск, AST → SSA-представление поверх операций
  `IReal`); эталонный разбор в Python (`prototype/geo4d/nodes/expr.py`) строит то же SSA и вычисляет его jet.ops.
  Тест: на наборе выражений C++ (команда `geo4d_gpu eval`) и Python дают одни значения и производные (float64).

### 3. Библиотека нод (`nodes/*.json`)
Нода — данные: тип, контекст, входы (тип, по умолчанию, диапазон для ползунка), выход, формула на языке выражений,
правила метаданных (тоже выражения над параметрами). Пользовательская нода — такой же файл (`%APPDATA%\geo4d\nodes`).

| группа | ноды |
|---|---|
| многообразия (8 нынешних, формулы — буква в букву из `scenes.slang`) | `mf.hyperplane`, `mf.S3`, `mf.spheritorus`, `mf.torisphere`, `mf.tiger`, `mf.ellis`, `mf.compact_wh`, `mf.two_compact_wh` |
| составные многообразия (M35, M37) | `mf.two_sheets` (база ±W), `mf.throat` (вставка в базу), `mf.formula` (выражение + объявленные метаданные) |
| преобразования (оба контекста) | `xf.translate`, `xf.rotate` (плоскость ij, угол), `xf.scale` (равномерный; неравномерный — только объекты, M36) |
| объекты | `obj.ball4`, `obj.torus` (в листе), `obj.halfspace`, `obj.box4` (скруглённый), `obj.capsule`, `obj.cylinder`, `obj.union` / `obj.intersect` / `obj.subtract` (гладкие, M36), `obj.formula` (+ L), `xf.on_M` (центр на M, оси — касательный базис), `obj.array` (≤ 32 объектов в сцене) |
| материалы | `mat.diffuse`, `mat.metal`, `mat.emit` (входы альбедо/шероховатость — константа или текстура; излучение — константа) |
| текстуры | `tex.coords` (мировые x ∈ R⁴ / локальные объекта / лист), `tex.checker`, `tex.grid`, `tex.stripes`, `tex.ramp`, `tex.noise`, `tex.fbm`, `tex.voronoi`, `tex.marble`, `tex.mix`, `tex.hsv`, `tex.formula` |
| математика (скаляры и поля) | `math.add/mul/…`, `math.formula`, `math.value` (параметр-скаляр) |
| выходы | `out.object` (форма + материал + имя), `out.scene` (многообразие, объекты, фон) |

Скалярные подграфы, не зависящие от точки (например, «радиус = 2·b»), вычисляются на CPU при каждой правке
параметров и пишутся в слоты (§5).

### 4. Кодген
- Заголовок сцены `pt_scene.slang` (в `gen/<хэш>/`) теперь содержит и многообразие: `sdf<T>`, `SCALE`, `hcap`,
  плоские зоны и выход (сейчас — дефайны и ветви `scenes.slang`); объекты — `obj_g<T>(k, …)`, ограничивающие сферы,
  признак полупространства; материалы — `mat_albedo(k, hit)`, `mat_rough(k, hit)` (текстуры).
- Формулы генерируются как вызовы `IReal`-операций в порядке SSA. Для нынешних 8 видов это тот же текст, что в
  `scenes.slang`, — кадры мигрированных сцен **побитово** равны нынешним при запечённых параметрах (`bake`; режим
  для тестов и для сравнения цены слотов).
- Ключ кэша SPIR-V — как сейчас (DD-010): хэш заголовка входит в ключ.
- CPU-вычисление того же SSA (double, дуальные по 4 направлениям) заменяет рукописные формулы `scene.cpp`
  (проекция `on_M` и камеры, `make_camera`) и даёт предпросмотры на нодах (DD-012).

### 5. Слоты параметров
- Каждый параметр ноды (и результат скалярного подграфа) — слот float в буфере параметров (`binding` — решить при
  реализации: хвост `gCam`, как строки DD-008, или отдельный буфер; DD-008 избегал новых привязок).
- Кодген читает слот (`P[17]`) вместо литерала; ползунок → запись слота → кадр секцией `edit` (сброс накопления), как
  правка объектов сейчас. Строки объектов DD-008 становятся частным случаем слотов.
- Бюджет: ≤ +5 % к кадру против запечённых параметров (сцена 3, 1080p). Если больше — параметры многообразия
  запекаются, их ползунок = структурная правка (предпросмотр сразу, компиляция в фоне).

### 6. Байткод и ядро предпросмотра
- Байткод — как в пробе (`geo4d.bytecode`, четыре пути над jet-числами), но строит его C++ из того же SSA; Python
  строит его тоже — для сверки (`bc_check`). Программы: многообразие f; g каждого объекта; текстуры. Операции:
  унарные (значение и две производные считаются скалярно по op), `±`, `·`, выбор по значению, загрузка слота,
  встроенные шум/вороной (только текстуры).
- Ядро предпросмотра (`pt_preview` из пробы) — первичная геодезическая, затенение «фонарь у камеры», G-буфер для
  наложений (длина, шаги, исход, id объекта, точка, нормаль, лист, флаги — сами наложения в DD-012). Варианты:
  нативный (кодген) и на интерпретаторе (шейдеры от сцены не зависят и поставляются скомпилированными).
- Структурная правка (до DD-012 — изменение файла `.g4d`): байткод → сразу кадр предпросмотра на интерпретаторе;
  в фоне — кодген и компиляция (DD-010); готово → нативный предпросмотр или рендер, как был выбран.
- Предел программы — например 1024 инструкции и 64 регистра на программу; превышение — только нативный путь.

### 7. Валидация графа
Типы портов и контексты (поле многообразия не соединить с полем объекта); запрещённые функции в геометрии; циклы;
обязательные входы; M37 (непересечение шаров, объявленные плоские зоны — численно); M36 (константа Липшица у
неравномерного масштаба и выражений); не больше 32 объектов. Ошибка — сообщение с id ноды и позицией в формуле;
окно остаётся на прежнем графе.

### 8. Окно до DD-012
`.g4d` открывается как сейчас JSON (кнопка «Открыть», аргумент `geo4d_gpu сцена.g4d`), файл отслеживается; панель
«Параметры» — ползунки всех параметров графа, сгруппированные по нодам. Старый редактор объектов и режим
редактирования (DD-008/009) работают для v1-сцен до DD-012 — промежуточного регресса нет. Когда v2-путь закрывает их
возможности, `SCENE_DYNAMIC`, `PT_DYNAMIC` и граф режима редактирования удаляются (их заменяют слоты и
интерпретатор).

### Порядок реализации (каждый шаг — с проверкой)
1. **Язык и SSA**: C++ (`expr`, `geo4d_gpu eval`) и Python; тест — значения и производные совпадают (float64).
2. **Библиотека и кодген**: 8 нынешних видов + объекты/материалы → `.g4d`, миграция v1; кадры мигрированных сцен
   побитово = нынешние (`bake`); CPU-SSA заменяет формулы `scene.cpp`.
3. **Новые ноды**: `mf.two_sheets`/`mf.throat` (M35), CSG и преобразования (M36), `mf.formula`/`obj.formula`
   (M37); GPU против прототипа ≤ 4× float32, геодезические против DOP853.
4. **Слоты** и панель «Параметры»; замер цены слотов.
5. **Байткод и предпросмотр** (нативный и на интерпретаторе), перезагрузка `.g4d`; `bc_check`; замер.
6. **Текстуры**: контекст, предустановки, свои; альбедо текстуры — в AOV денойзера.

## Рассмотренные альтернативы и почему отвергнуты
- **Один универсальный граф полей** (как SDF-редакторы): нельзя вывести `hcap`, плоские зоны и выход — интегратор
  туннелирует сквозь кривизну (known-issues, «Туннелирование»), NEE неверна. Отвергнуто ещё в концепции.
- **CSG над многообразиями через smin** (объединение «тел»): даёт связную сумму, но гладкая склейка вносит кривизну с
  масштабом k и ломает метаданные; составная база + вставки (M35) покрывает нужное (горловины между листами) честно.
- **Ноды как C++/Slang-код** (без языка выражений): каждая нода — две реализации (Slang и Python) плюс байткод;
  язык выражений даёт одну формулу на ноду и бесплатно — пользовательские ноды.
- **Готовая библиотека выражений** (exprtk, muparser): нужны свои типы (jet-числа), контексты и вывод в Slang и
  байткод — от библиотеки остался бы только лексер.
- **Интерпретатор и для рендера** — отклонён пробой (15–24× медленнее).

## Бюджет производительности и памяти
- Кадр нативного пути: мигрированные сцены с `bake` — без изменений (побитово); со слотами — ≤ +5 %.
- Структурная правка: кадр предпросмотра на интерпретаторе — следующий кадр (55 мс в 720p у двух горловин по пробе;
  с объектами — замерить); нативная сборка — ~2 с (DD-010).
- Разбор и кодген графа из 100 нод — ≤ 10 мс (замерить).
- Байткод: ≤ 1024 инструкций × 16 Б на программу, ≤ 34 программы — сотни КБ максимум.

## План проверки
- Язык: C++ = Python (значения, градиенты, гессианы) на наборе выражений; запрещённые функции в геометрии — ошибка
  разбора.
- Миграция: v1 → v2 → строки буфера, заголовок и кадр побитово (`bake`); круговой обмен `.g4d`.
- Новые ноды: M35 против M12; M36 (липшицевость и граница расстояния) на точках; геодезические через горловины
  составного многообразия — DOP853; GPU против прототипа ≤ 4× float32.
- Слоты: кадр со слотами = кадр с `bake` в пределах округления (как `test_dynamic_manifold_matches_baked`); правка
  ползунка = холодный старт с тем же значением (побитово, как DD-008).
- Байткод: интерпретатор = нативный путь в пределах округления (как `test_gpu_prog`); `bc_check` C++ = Python.
- Окно: перезагрузка `.g4d` со структурной правкой — предпросмотр в следующем кадре, затем нативный кадр =
  холодный старт изменённой сцены (побитово).
- Замеры: цена слотов, кадр предпросмотра с объектами, разбор и кодген — в `results/stage-5/…_nodes_*`.

## Риски и открытые вопросы
1. **Цена слотов** в горячем коде SDF (§5) — замер решит, запекать ли параметры многообразия.
2. **Объекты в интерпретаторе предпросмотра** ещё не мерились: g вычисляется на каждом шаге луча — кадр
   предпросмотра может стать заметно дороже 55 мс; запасной вариант — ограничивающие сферы и пропуск далёких объектов
   (уже есть в нативном пути).
3. **Метаданные выражений** (M37): численная проверка ловит не всё; ошибка в объявлении плоской зоны даёт
   туннелирование. Смягчение — по умолчанию «вид неизвестен» (консервативно).
4. **Совпадение порядка операций** для побитовой миграции: если кодген не сможет воспроизвести формулы
   `scenes.slang` буква в букву, критерий — пределы округления и сверка с прототипом.
5. **Известная проблема** (пурпурный пиксель режима A, known-issues) не связана с нодами, но побитовые тесты окна
   больше 8192 пикселей могут изредка падать — тесты этого DD идут в малых разрешениях.
