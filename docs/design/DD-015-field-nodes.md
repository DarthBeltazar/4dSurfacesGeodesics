# DD-015: одна нода «поле 4D» для двух ролей (многообразие и объект)
Статус: **Accepted** (пользователь 2026-10-27: старые ноды — скрыть из меню; `xf.*` для многообразий — вместе с нодами)
Этап: после 5 (нодовая система, [DD-011](DD-011-node-graph-core.md); пожелание пользователя — [TODO](../TODO.md), п. 2)
Дата: 2026-10-27

## Контекст и задача
Сейчас шар, гиперплоскость и формула существуют в двух экземплярах: `mf.sphere` / `obj.ball4`, `mf.hyperplane` /
`obj.halfspace`, `mf.formula` / (у объектов формулы нет). Порты типизированы строго (`manifold` ≠ `shape`), проверка —
точное совпадение строк в двух местах (`node_editor.cpp:246`, `scene_graph.cpp:356`). Пользователь хочет одну ноду
на каждое поле, роль — по выходу, к которому она подключена; проверки — по роли; неподходящие для роли ноды не
подключаются с пояснением; преобразования `xf.*` — в обоих контекстах; в меню — группа «Поля» (решения TODO, п. 2).

## Цели / не-цели
Цели:
- ноды `fld.ball` (c ∈ R⁴, R), `fld.halfspace` (axis, offset, sign), `fld.formula` (формула, a…d; параметры ролей:
  scale и s_max — многообразие, L — объект); выход — новый тип порта `field`;
- роль выводится по графу, проверки — по роли: многообразие — гладкость и метаданные (M37/M38/M39), объект —
  граница расстояния и константа Липшица (M36);
- одно правило типов вместо двух проверок строк (см. §1); понятные сообщения, какая нода «закрепила» тип;
- кадры старых сцен и сцен с `fld.*` вместо старых нод — те же (тот же текст шейдеров и ключ структуры);
- `xf.translate` / `xf.rotate` / `xf.scale` в роли многообразия с выводом метаданных (M40) — в этом же шаге.

Не-цели: объединение операций CSG в одну ноду для двух ролей (у многообразия — M38 csmin с компактным носителем, у
объекта — экспоненциальный smin M36: разная математика, кадры объектов изменились бы; остаются `mf.union…` и
`obj.union…`, обе группы — рядом с «Полями»); поворот, смешивающий w, у многообразия с плоской основой (v1 — ошибка);
тор как многообразие; текстуры (шаг 7 DD-011).

## Математика
Новых формул в шаге 1 нет: роли отображаются на имеющиеся пути.

| нода | роль «многообразие» | роль «объект» |
|---|---|---|
| `fld.ball` | кусок CSG `mf.sphere` (M38); одна — замкнутое S³ с центром, s_max = 8πR | прежний вид `ball4` (строки, побитово) |
| `fld.halfspace` | основа-гиперплоскость w = offset (axis = w обязательно; sign — сторона «внутри» w < offset при sign > 0) | прежний вид `plane` (axis, offset, sign) |
| `fld.formula` | `mf.formula` (M37: шаг ≤ scale, без плоских зон, s_max) | новое: g/L, контекст «геометрия» (гладкие функции), неограниченная (как полупространство: без ограничивающей сферы, `xf.on_M` — ошибка) |

Объект-формула — единственная новая математика шага 1: трассировщик пока не делит g на L (M36 обещал, но объявлять
L было нечем). g/L с L ≥ |∇g| сохраняет требование M26; проверка — на выборке |∇g|/L ≤ 1 + ε (предупреждение у
ноды, если нет).

**M40 (черн.)** — метаданные многообразия при преобразованиях: сдвиг (t_q, t_w) — листы
w + t_w, центры шаров c_q + t_q; поворот в плоскости из осей x, y, z — поворот центров (листы и полосы M39 не
меняются, L та же); масштаб s — листы, центры, радиусы шаров ×s, ℓ_s ×s, s_max ×s, k узлов ×s (L та же: f(p/s)·s).
Проверка в прототипе: `shapes.transformed` (U6) + выведенные метаданные дают ту же ошибку геодезических против
DOP853, что и исходная фигура; затравки выборки κ (`csg_curvature`) — в преобразованных координатах.

## Предлагаемое решение
1. **Правило типов** (одна функция `port_accepts(input, source)` в `scene_graph.cpp`, её зовут и редактор, и
   загрузка): у входа — множество допустимых типов: роль «многообразие» (`scene.manifold`, входы `mf.union/…`) —
   {manifold, field} (`mf.throat.base` — только «Два листа», как сейчас); роль «объект» (`out.object.shape`, входы `obj.*`, `xf.on_M`) — {shape,
   field}. Выход `xf.*` — тип его входа (вверх по цепочке `xf`); `xf.*` над `field` остаётся `field`. Так
   `mf.ellis → xf → out.object` и `obj.union → scene.manifold` отклоняются по типу; сообщение называет ноду,
   закрепившую тип («“Эллис” — только многообразие»).
2. **Роль при сборке**: обход от `scene.manifold` — роль многообразия, от `out.object` — объекта; `fld.*` читается
   в каждой роли своим кодом (`piece()` для многообразия, `shape_of()`/прежние виды для объекта). Одна нода в обеих
   ролях сразу — допустима (тест).
3. **Старые типы** (`mf.sphere`, `mf.hyperplane`, `obj.ball4`, `obj.halfspace`, `mf.formula`) — см. вопрос 1.
4. **Редактор**: группа «Поля», цвет порта `field`, значок роли на ноде (М / О / обе), инспектор показывает
   параметры роли (у формулы scale и s_max — для многообразия, L — для объекта), неиспользуемые — серым.
5. **Предпросмотр** (байткод): новые ноды отображаются на прежние пути — `bc_check`, jet-числа интерпретатора и
   сравнение предпросмотра с нативным — на сценах с `fld.*` в обеих ролях.
6. **Объект-формула**: `Object.kind = "graph"` с выражением g·(1/L) (L — слот), ограничивающей сферы нет.

## Рассмотренные альтернативы
- **Чёрный список «нельзя как объект / как многообразие»** в редакторе — отклонено: правило типов (§1) даёт то же
  без списка и само работает для новых нод.
- **Одна нода CSG для двух ролей** — отклонено в v1 (см. не-цели).
- **Роль как параметр ноды** (переключатель) — отклонено: TODO требует роль по выходу; переключатель расходился бы
  со связями.

## Бюджет
Кадры — без изменений (те же пути и тексты шейдеров). Загрузка — +1 обход графа (мкс).

## План проверки
- Для каждой сцены `scenes/*.g4d`: копия с `fld.*` вместо старых нод даёт тот же текст `mf_scene.slang`/
  `pt_scene.slang` и тот же ключ структуры (`eval-graph`).
- Правило типов: таблица допустимых/отклонённых связей (вход × источник через цепочки `xf`), сообщения.
- Одна `fld.ball` в двух ролях; объект-формула (шар формулой = `ball4` в пределах округления; L < |∇g| —
  предупреждение); `--legacy-codegen` и прежние побитовые тесты — без изменений.
- M40: прототип (U6 + метаданные), затем окно: геодезические против DOP853 ≤ 4× прототипа float32.

## Решения пользователя (2026-10-27)
1. Старые ноды остаются загружаемыми и скрыты из меню (`"hidden": true`), файлы не переписываются.
2. `xf.*` для многообразий — в одном шаге с нодами полей. Область v1: куски графа (поля, листы с горловинами, CSG,
   формула); виды каталога (S³, Эллис, торы…) под `xf` — ошибка с подсказкой «используйте поле или формулу»;
   поворот, смешивающий w, у куска с листами или горловинами — ошибка.
