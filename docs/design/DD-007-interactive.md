# DD-007: Интерактивная камера и офлайн-ролик
Статус: **Accepted** (принят самостоятельно: ревью пользователя обязательно только для DD-004 и DD-005; журнал 2026-10-24-06)
Этап: 5        Дата: 2026-10-24

## Контекст и задача
TASK.md, этап 5 (опционально): интерактивная камера — WASD, полёт сквозь горловину с переходом между листами,
свободный полёт по S³ и торам; офлайн-рендер ролика по пути камеры. Есть: кадр режима B одним командным буфером
(`render_frame_graph`), денойзер OptiX через копии хост ↔ GPU (ADR-0007), хост без окна.

## Цели / не-цели
**Цели:** окно с управлением (WASD + мышь), движение камеры *по многообразию* (геодезические, перенос базиса),
накопление при неподвижной камере, денойзер без копий через хост, сцены S³ и торов с объектами-источниками, ролик
1080p по пути камеры с переходом между листами; измерить время кадра в окне.
**Не-цели:** UI/меню, загрузка произвольных сцен в рантайме (сцена выбирается при запуске), Linux/macOS-окно,
временная репроекция при движении (накопление сбрасывается при движении).

## Математика
**M33 (черн.). Движение камеры по M.** Камера — точка x ∈ M и ортонормированный касательный базис (f, r, u).
- Поворот (рыскание ψ, тангаж θ, крен φ) — вращение базиса внутри T_xM: f, r вокруг u на ψ; f, u вокруг r на θ;
  r, u вокруг f на φ. Базис остаётся касательным и ортонормированным точно.
- Перемещение на вектор m = a·f + b·r + c·u (|m| = s за кадр): геодезическая из x в направлении m/|m| длины s
  (BS32 с фиксированным числом подшагов + проекция M3), базис переносится параллельно проекцией после каждого
  подшага (как M32) с Грам–Шмидтом. Переход между листами — свойство геодезической, отдельной логики нет.
- Столкновения: шаг отменяется, если g_min(x_new) < margin (камера не входит в объекты).
- Проверка (прототип): на S³ — прохождение 2πR возвращает в исходную точку с тем же базисом (голономия вдоль
  геодезической тривиальна) и точное решение M13; в плоской зоне — прямая; компактная червоточина — радиальный полёт
  меняет лист (sign w) и база остаётся ортонормированной; GPU `cam_step` против прототипа.

## Предлагаемое решение
1. **Хост:** граф (`graph.cpp`) выносится в загружаемую программу `GraphProgram` с **секциями** (`section <имя>`) и
   изменением push-констант во время работы. Подкоманда `geo4d_gpu app <graph.txt>`: окно SDL3 (из Vulkan SDK),
   swapchain, цикл кадра. Секции: `move` (шаг камеры → проход камеры → режим A → списки → сброс накопления →
   трассировщик 1 spp + фолбэк → сборка), `static` (ещё 1 spp + фолбэк → сборка), `post` (вставка фона режима A после
   денойзера, тонмаппинг, упаковка RGBA8). Хост: ввод → секция → денойзер → `post` → копия в образ swapchain → present.
2. **Денойзер без копий:** буферы цвета/AOV/выхода создаются с экспортом памяти (`VK_KHR_external_memory_win32`),
   импортируются в CUDA (`cuImportExternalMemory`, `cuExternalMemoryGetMappedBuffer`); синхронизация — ожиданием на
   CPU (Vulkan завершён → OptiX → `cuStreamSynchronize` → Vulkan). Структуры CUDA — в шиме `cuda.h` (ADR-0007).
3. **Ядра** (pathtrace.slang): `cam_step` (M33, 1 поток, состояние камеры — в буфере GPU), `pt_reset`, `pt_compose`,
   `pt_present`.
4. **Сцены:** S³, «сферитор», «ториосфера» с излучающими и диффузными шарами (фона нет — только трассировщик;
   плоских зон нет — только BSDF-сэмплирование); сцена 3 и Эллис — как на этапе 4.
5. **Запуск:** `prototype/scripts/app.py --scene … --res …` генерирует сцену, шейдеры и граф, запускает хост.
   Режим замера: сценарий движения на N кадров, скрытое окно, журнал времени кадров (JSON).
6. **Ролик:** `prototype/scripts/video.py` — путь камеры из M33 в прототипе (полёт сквозь горловину с поворотом),
   кадры `render_frame_graph` (64 spp) + денойзер + фон режима A → PNG → ffmpeg (H.264).

## Рассмотренные альтернативы
- Камера по евклидовым координатам с проекцией на M — не проходит горловину корректно (проекция «перескакивает»
  на ближайший лист), не даёт параллельного переноса.
- Синхронизация Vulkan ↔ CUDA семафорами — быстрее, но сложнее; ожидание на CPU сначала, замерить.
- Временная репроекция при движении — вне объёма.

## Бюджет
1080p сцена 3: 51 мс на кадр (этап 4) + present + шаг камеры (< 0.1 мс) ⇒ ≈ 20 кадров/с; для плавности — окно 720p
(≈ 2.2× меньше пикселей). Измерить.

## План проверки
Тесты M33 в прототипе (выше); `cam_step` GPU против прототипа; денойзер через обмен памятью = денойзер через копии;
замер времени кадра в окне (движение/покой, 720p/1080p); ролик собран, длительность и кадры проверены.

## Риски
Совместимость раскладки структур CUDA в шиме (проверка — побайтовое совпадение с путём через копии); swapchain без
TRANSFER_DST (тогда — копия через образ-посредник).
