## 1. В работающем приложении нет Python
Python остаётся для разработки: прототип, эталон, тесты. В программе пользователя его нет (сейчас релиз v0.1.0-alpha
требует Python 3.12 и ~1.5 ГБ `.venv`).

| Сейчас (Python в `app.py`) | Станет (C++ хост) |
|---|---|
| `gpu_pt.app_graph`: граф кадра | граф строится в хосте; текстовый формат графа остаётся для тестов (`run`/`graph`) |
| `scene_header` и дефайны `MF_*` | кодген из графа нод в Slang |
| `slangc.exe` отдельным процессом | Slang как библиотека в процессе, прекомпилированные модули `jet`/`scenes`/`pathtrace` |
| процедурный фон в JAX | compute-шейдер; плюс нода «Окружение» с загрузкой HDRI |
| самодельный разбор JSON | JSON-библиотека (FetchContent, закреплённая версия) |
| смена разрешения через Python (2.3 с) | пересчёт размеров буферов в хосте |

Шейдеры предпросмотра на интерпретаторе от сцены не зависят и поставляются заранее скомпилированными: любая сцена
открывается сразу в предпросмотре (п. 3), нативные шейдеры компилируются в фоне (~2 с) или берутся из кэша на диске
(SPIR-V и `VkPipelineCache`); для предустановленных сцен SPIR-V идёт в комплекте.

## 2. Нодовая система
**Три контекста с типизированными портами** (соединять их между собой нельзя):

| Контекст | Требования | Разрешённые функции |
|---|---|---|
| Многообразие f | C², ∇f ≠ 0 на M; метаданные ℓ_s, `hcap`, плоские зоны и листы (M29/M34), выход режима A, наличие фона | арифметика, sqrt и length с защитой от нуля, exp, log, sin, cos, cosh, tanh, целая степень, smin / smax / sabs |
| Объект g | 1-липшицева, не больше расстояния до {g = 0} (M26); ограничивающая сфера | то же; ∩ и − в консервативном варианте |
| Текстура / материал | нет требований к гладкости | всё, включая floor, fract, mod, step, min, max, abs, сравнения |

- **Многообразие.** Основы (гиперплоскость, два листа, S³, S²×R, S¹×R², эллипсоид, торы, Эллис) и вставки в плоские
  листы (горловина: c, b, ρ₀, со своим шаром носителя). Комбинация здесь — сложение профилей на плоской основе
  (h₁ + h₂ − W², как в M12), а не smin. Преобразования только жёсткие в R⁴ и равномерный масштаб. Метаданные
  передаются по графу, `hcap` и список плоских зон собираются сами. Для ноды-выражения метаданные задаются вручную,
  по умолчанию консервативные. Проверка: vᵀHv ≈ 0 вне объявленных носителей, min |∇f| по выборке точек M.
- **Объекты.** ball4, тор в листе, полупространство, скруглённый box4, капсула, цилиндр; гладкие ∪/∩/− с радиусом k;
  нода «Поставить на M» (проекция центра + выравнивание по касательному базису); «Массив» не больше `PT_MAXOBJ` = 32.
  Попадание засчитывается только по смене знака g, поэтому для тонких деталей на ноде есть предупреждение.
- **Материалы.** Диффузный, металл, излучатель. На ноде показано, может ли источник быть NEE-источником по M34
  (если нет — только BSDF, шумнее).
- **Текстуры.** Вычисляются в 4D-точке попадания (объёмная текстура, развёртка не нужна). Координаты: мировые x ∈ R⁴
  (по умолчанию), локальные координаты объекта, номер листа / знак w. Предустановки (каждая — подграф с вынесенными
  параметрами): 4D-шахматка, координатная сетка, полосы и кольца, градиент или цветовая шкала, шум (value/gradient,
  fBm), Вороной, мрамор. Свои текстуры собираются из математических и цветовых нод (Mix, Ramp, HSV, Remap). В v1
  текстура идёт в альбедо и шероховатость; в буфер альбедо денойзера пишется текстурное альбедо. Шум и Вороной —
  встроенные инструкции.
- **Формы записи:** граф мелких нод и нода «Формула» с текстом; обе дают одно внутреннее представление графа.

**«SDF пишется один раз» без Python в приложении.** Библиотека нод — данные (`nodes/*.json`: входы, параметры,
контекст, формула на языке выражений, метаданные). C++ из одного разбора выдаёт Slang (шейдеры),
байткод (предпросмотр на GPU, п. 3) и CPU-интерпретатор (предпросмотры на нодах). Python в тестах разбирает тот же язык в jet.ops:
эталон с DOP853 и критерий ≤ 4× float32. Тесты сравнивают числа (f, ∇f, vᵀHv, g в наборе точек), а не тексты.
Пользовательская нода — такой же файл.

## 3. Режим редактирования: проба интерпретатора (сделана) и что из неё следует
**Проба** (журнал [2026-10-25-02](../log/2026-10-25-02.md), коммит 8014773): `geo4d.bytecode` (SSA → регистры,
эталон на jet.ops), интерпретатор в `scenes.slang` под `MF_PROG` (режим редактирования, f из программы в хвосте
буфера камеры; hcap, выход и плоские зоны — как у зашитого вида). Точность — как у нативного кода
(`tests/test_gpu_prog.py`: ошибки Jet7/HVP/Jet15 ~1e-6 против float64, у зашитой сцены те же).

| Режим редактирования (движение / покой, мс) | 720p | 1080p |
|---|---|---|
| нынешний (f нативно, вид из строк) — [база](../../results/stage-5/2026-10-25_app_bench_two_wormholes_1280x720_probe_base) | 29.4 / 8.7 | 58.5 / 18.2 |
| интерпретатор, 45 инструкций, 4 пути над jet — [interp](../../results/stage-5/2026-10-25_app_bench_two_wormholes_1280x720_probe_interp) | 592 / 144 | 1392 / 324 |
| то же, программа зашита константами — [const](../../results/stage-5/2026-10-25_app_bench_two_wormholes_1280x720_probe_interp_const) | 561 / 132 | 1289 / 303 |
| то же, регистры без динамического индекса — [static](../../results/stage-5/2026-10-25_app_bench_two_wormholes_1280x720_probe_interp_static) | 1045 / 232 | — |
| S³: нативно / интерпретатор, 9 инструкций — [S3](../../results/stage-5/2026-10-25_app_bench_S3_1280x720_probe_interp) | 20.7 → 304 | — |

- **Интерпретатор в 15–24 раза медленнее**, и цена почти не зависит от длины программы (S³ — 9 инструкций, ×15).
  Чтение инструкций из буфера ни при чём (константы дают −5 %). Причина — jet-регистры с динамическим индексом
  в локальной памяти: драйвер показывает 2816 байт локальной памяти на поток у `prog_u1` против 0 у `jets_u1`.
  Развёрнутый выбор регистров ещё хуже. Кадр 0.6–1.4 с — режимом редактирования это быть не может.
- **Перекомпиляция** ([probe_compile](../../results/stage-5/2026-10-25_probe_compile), сцена с новым b — промах и slangc, и кэша драйвера):

  | slangc | последовательно | параллельно (процесс на ядро) | конвейеры драйвером, промах | кадр быстрого графа 720p |
  |---|---|---|---|---|
  | -O2 | 3.79 с (`pt_sample` 1.75) | 1.83 с | 0.74 с (`pt_sample` 0.41) | 16.9 / 7.0 мс |
  | -O0 | 2.09 с | 0.48 с | 1.98 с (`pt_sample` 1.36) | 20.0 / 8.1 мс (+18 %) |

  Пустое ядро в slangc — 0.14 с (процесс + базовый модуль; уйдёт при Slang внутри хоста). Повторная сборка
  конвейеров из кэша драйвера — 2 мс. Оценка задержки структурной правки: **~2 с** (−O2, ядра параллельно, сборка
  конвейеров параллельно), задаёт её `pt_sample`.

**Вывод пробы полного кадра.** Мгновенные структурные правки через интерпретатор в полном рендере стоят 15–24×
времени кадра — отклонено.

**Проба режима предпросмотра** (предложение пользователя, [probe_preview](../../results/stage-5/2026-10-25_probe_preview); ядро `pt_preview`: одна первичная
геодезическая через центр пикселя, Jet7, без полей Якоби, отскоков и фолбэка; затенение «фонарь у камеры», фон по
направлению выхода; [кадр интерпретатора 720p](../../results/stage-5/2026-10-25_probe_preview/two_wormholes_1280x720_interp.png)). Время ядра, мс:

| сцена | 640×360 | 960×540 | 1280×720 | 1920×1080 |
|---|---|---|---|---|
| две горловины, нативно | 0.52 | 0.85 | 1.47 | 3.35 |
| две горловины, интерпретатор | 17.3 | 29.7 | 55.4 | 138 |
| S³ (s ≤ 8πR, как в рендере), нативно / интерпретатор | 3.3 / 38.9 | 7.0 / 93.7 | 13.3 / 183 | 33.3 / 464 |
| S³, предпросмотр до одного оборота s ≤ 2πR, нативно / интерпретатор | 0.84 / 9.4 | 1.9 / 22.4 | 3.5 / 44.1 | 8.9 / 114 |

Полный кадр той же сцены в режиме редактирования — 29.4 мс (720p). Сборка самого `pt_preview` при промахе кэшей:
−O2 — slangc 1.11 с + драйвер 0.22 с; −O0 — 0.40 + 0.90 с. То есть и маленькое ядро нативно собирается ~1.3 с —
мгновенным предпросмотр даёт только интерпретатор.

- Интерпретатор в предпросмотре — 30–60 кадров/с при половинном разрешении (720p-окно: 17 мс у двух горловин,
  9 мс у S³ с пределом в один оборот), ~18–23 кадров/с в 720p. Это пригодно для правки.
- Нативный предпросмотр — 1.5 мс в 720p: и сам по себе полезен (быстрая навигация, проверка геометрии без шума).
- Не замерено: объекты сейчас в предпросмотре нативные (строки DD-008); их графы тоже придётся интерпретировать —
  цена добавится к каждому шагу.

**Схема (принята пользователем, журнал 2026-10-25-02):**
- режимы вьюпорта: «Предпросмотр» (первичные геодезические, затенение, наложения: туман по длине, тепловая карта
  шагов, листы) и «Рендер» (трассировщик, режим A, денойзер);
- структурная правка → сразу предпросмотр на **интерпретаторе** (шейдеры не зависят от сцены и поставляются
  скомпилированными; разрешение адаптивное под ≥ 30 кадров/с), в фоне — нативная компиляция предпросмотра и рендера
  (~2 с, ядра параллельно), затем переход на нативные ядра (в «Рендер», если пользователь был в нём);
- параметры — мгновенны везде (слоты в буфере).

## 4. Интерфейс
### Компоновка (решение пользователя)
- **Основной вьюпорт** — центр окна, его нельзя закрыть или перекрыть: центральный узел dockspace ImGui (ветка
  docking, закреплённый коммит), прикрепление поверх него запрещено. Картинка рисуется в его прямоугольнике (blit с
  полями); разрешение «как вьюпорт» пересчитывается через 0.4 с после остановки разделителя.
- **В правом верхнем углу вьюпорта** — кнопка настроек (шестерёнка), рядом переключатель режима
  «Предпросмотр / Рендер». Всплывающее окно настроек: режим, затенение предпросмотра, наложения (ниже), разрешение
  (доля вьюпорта или фиксированное, адаптивное в предпросмотре), экспозиция, денойзер, скорость камеры, строка
  статистики.
- **Остальные меню пристёгиваются к сторонам вьюпорта** (слева, справа, снизу, сверху), объединяются вкладками,
  сворачиваются и отцепляются в отдельные окна. Панели: «Ноды», «Инспектор» (параметры выбранной ноды), «Сцена»
  (список объектов и многообразие), «Рендер» (настройки трассировщика), «Журнал» (сообщения, ошибки компиляции).
  Компоновка сохраняется в `%APPDATA%\geo4d`, в меню «Окно» — «Сбросить компоновку». По умолчанию: «Сцена» слева,
  «Инспектор» справа, «Ноды» снизу.
- Сверху — главное меню: «Файл» (Новый, Открыть, Сохранить, Сохранить как, Недавние), «Правка» (undo/redo —
  снимки JSON графа), «Рендер» (кадр в PNG/EXR, видео по пути камеры), «Окно», «Справка» (клавиши).
- Во вьюпорте: клик выделяет объект (по буферу id), перетаскивание — сдвиг в касательном базисе камеры с проекцией
  на M; двойной клик по ноде — её выход во вьюпорте (флаг отображения, как в Houdini).
- Предпросмотры на нодах — на CPU: срез текстуры 64×64, профиль h(ρ), срез поля с нулевой линией.

### Наложения (решение пользователя: настраиваемые и во всех режимах)
**Как устроено.** Наложения строятся из G-буфера центрального луча пикселя и смешиваются с кадром после тонмаппинга
(в `pt_present`), поэтому одинаково работают в предпросмотре и в рендере и не влияют на накопление и денойзер.
G-буфер (на пиксель): длина геодезической s, число шагов / вызовов SDF, исход (уход / попадание / потолок шагов),
id объекта, 4D-точка попадания, касательная нормаль, лист (знак w), флаги (прошёл через носитель кривизны,
неустойчивая орбита, пиксель режима A / трассировщика / фолбэка).
- Предпросмотр: G-буфер пишет само ядро предпросмотра (его затенение — тоже функция G-буфера).
- Рендер: в сценах с фоном центральные лучи уже трассирует проход камеры — G-буфер пишет он; в компактных
  пространствах (без прохода камеры) при включённых наложениях добавляется проход предпросмотра (нативно 1.5 мс в
  720p у двух горловин, 3.5–13 мс у S³ — проба п. 3). Только в кадрах с движением или правкой: в покое G-буфер
  прежний.

**Набор наложений** — у каждого: вкл/выкл, непрозрачность, своя настройка; общий переключатель всех (клавиша):
| наложение | настройка |
|---|---|
| туман по длине геодезической | цвет, расстояние начала и полной плотности |
| тепловая карта шагов / вызовов SDF | шкала, диапазон (авто или вручную) |
| исход луча и флаги: потолок шагов, неустойчивые орбиты, пиксели фолбэка | цвета флагов, какие показывать |
| лист / «вселенная» (знак w) | цвета листов |
| координатная сетка на поверхностях (линии x, y, z, w = const в 4D-точке попадания) | шаг, толщина, оси |
| носители кривизны: где луч проходил через область кривизны | цвет |
| нормали (ложный цвет), id объекта | — |
| контур выделенного объекта (по id) | цвет, толщина |
| строка статистики: кадры/с, spp, время проходов, разрешение, режим (интерпретатор / нативно, идёт компиляция) | состав |

Настройки наложений — свойство вьюпорта (сохраняются в настройках приложения, не в файле сцены).

## 5. Файл сцены и поставка
- Формат `.g4d` (JSON): `{"version": 2, "graphs": {"main": {nodes, links, outputs}}, "camera", "render"}`.
  `graphs` — словарь с первого дня (подграфы — новые записи и нода `subgraph`); компилятор работает в два шага:
  развернуть в плоский граф → инструкции. Старые `scenes/*.json` открываются миграцией; тест кругового обмена.
- Zip для Windows: exe, SDL3, slang-библиотеки, рантайм MSVC (или /MT), прекомпилированные SPIR-V (режим
  редактирования + предустановленные сцены), библиотека нод, сцены, текстуры, файл лицензий. Не нужны Vulkan SDK,
  Python, CUDA Toolkit.
- Кэш шейдеров — `%LOCALAPPDATA%\geo4d\cache`, настройки и пользовательские ноды — `%APPDATA%\geo4d`.
- Проверка GPU при старте с понятным сообщением; денойзер необязателен; журнал и отчёт о падении в пользовательский
  каталог.
