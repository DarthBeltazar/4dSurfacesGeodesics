# DD-004: Архитектура GPU (язык, wavefront-очереди, раскладка данных, бюджет регистров)
Статус: **Accepted** (ревью пользователя 2026-10-24, решения — в конце документа)
Этап: 3        Дата: 2026-10-24

## Контекст и задача
Перенести интегратор (DD-001), поля Якоби и режим A (DD-003) на GPU во float32 с jet-числами. Критерии этапа 3:
весь набор фигур и червоточин; расхождение с прототипом на уровне ошибок float32 (таблица по фигурам);
профилирование (мс на кадр 1080p и 4K, шагов на луч, занятость); ориентир режима A 1080p — 20–60 мс.

Окружение (проверено 2026-10-24): RTX 4080 SUPER (16 ГБ, sm 8.9, subgroup 32, BC-форматы, float64 в шейдерах),
драйвер 610.88, Vulkan 1.4.341; Vulkan SDK 1.4.328.1 (slangc 2025.17.2, dxc, spirv-tools, VMA, volk, SDL3);
MSVC 14.44, CMake и Ninja из CLion. **CUDA Toolkit и Nsight не установлены.**

## Цели / не-цели
- Цели: тот же алгоритм, что в прототипе (BS32 + FSAL «stale», проекция M3, α = 0.1/ℓ_s, hcap, M8, Якоби M15,
  режим A M18–M20), во float32; воспроизводимое сравнение с прототипом; измеренный профиль.
- Не-цели: path tracing (DD-005), окно и интерактив (этап 5), оптимизация до прохождения тестов.

## Математика
Без новых формул. Новое: тип jet-чисел «HVP» (см. ниже) — это новая формула, она сначала проверяется
в прототипе тестом U1 и только потом переносится.

## Предлагаемое решение

### 1. Язык и сборка
**Slang → SPIR-V → Vulkan 1.3 compute**, хост на C++20.
- Почему не CUDA: CUDA Toolkit не установлен, Slang/Vulkan SDK уже стоят. Slang кросс-вендорный и умеет
  обобщённое программирование, нужное для «SDF пишутся один раз».
- **Спайк (2026-10-24, scratchpad, вне репозитория):** обобщённая SDF Эллиса через интерфейс `IReal`
  и перегруженные `operator+/−/*` над пользовательскими структурами скомпилирована slangc в SPIR-V для float,
  Jet7 и Jet15 и прошла `spirv-val` (1.1 / 4.6 / 9.7 КБ). На GPU спайк не запускался.
- Jet-числа пишутся руками (структуры + операторы), повторяя алгебру M4/M5, проверенную U1.
  Встроенное AD Slang — только кандидат для производной выхода (п. 7).
- Зависимости только из SDK: volk, VMA. Окна нет (headless compute). SDL3 — на этапе 5.
- Сборка: CMake + Ninja + MSVC. Шейдеры компилируются slangc на этапе сборки; специализация по сцене —
  через generic-параметр сцены (одна точка входа на сцену и режим, без динамического ветвления по сцене).

Раскладка репозитория: `gpu/CMakeLists.txt`, `gpu/src/` (хост), `gpu/shaders/` (`jet.slang`, `scenes/*.slang`,
`integrator.slang`, `jacobi.slang`, `modea.slang`, `wavefront/*.slang`), `gpu/tools/` (кодировщик BC6H).

### 2. Точность float32 (главный риск №1)
- Все вычисления float32; позиции до |x| ≈ 20 (Эллис, ℓ_max = 20) ⇒ ulp ≈ 2e-6.
  При 1080p и fov 90° θ_pix ≈ 1e-3, при κ = 1e-3 (ADR-0002) tol ≈ 1e-6 — на уровне округления.
- Меры:
  - оценка ошибки — только из линейных комбинаций стадий (как в прототипе), никогда из разности больших
    абсолютных состояний;
  - в Эллисе f = ρ − b·cosh(w/b) при большом ℓ — вычитание близких чисел; проверить остаток проекции
    и при необходимости переписать f в эквивалентной форме без потери значащих цифр;
  - нижняя граница tol_min (≈ 64·ulp(|x|)/ℓ_s) — tol не опускается ниже неё.
- **Правило выбора κ для float32 — заранее:** повторить на GPU бенчмарк первичных лучей этапа 1 (p99 ошибки
  направления в θ_pix против κ, эталон — прототип float64 DOPRI5 tol 1e-12). Взять наименьшую стоимость
  при p99 ≤ 0.05 θ_pix; если это недостижимо из-за округления — максимальную достижимую точность и запись
  в ADR. Отдельно пересмотреть α (ADR-0001) во float32: развёртка α ∈ {0, 0.1, 1}/ℓ_s.

### 3. Критерий «расхождение на уровне ошибок float32» (определён до результатов)
Нужен эталон float32, иначе на хаотичных фигурах («тигр») любой фиксированный порог произволен.
- Прототип получает переключатель точности (`GEO4D_X64=0`). Те же начальные состояния (`.npy`) прогоняются
  тремя способами: GPU-f32, прототип-f32, прототип-f64; эталон — DOP853 f64 (rtol 1e-12).
- Метрика по фигуре: e_gpu = max‖GPU − DOP853‖ и e_p32 = max‖прототип-f32 − DOP853‖ по позиции и направлению
  при длине пути L и по выходам Якоби (∂x, ∂v).
- **Критерий: e_gpu / e_p32 ≤ 4 на каждой фигуре** и e_gpu не хуже, чем у прототипа-f64 при tol 1e-6
  в 10 и более раз. Таблица по фигурам — в отчёте этапа.

### 4. Регистры (главный риск №2) — решается измерением
Числа регистров и спиллы читаются через `VK_KHR_pipeline_executable_properties` (проверить, что именно
отдаёт драйвер NVIDIA); занятость вычисляется по регистрам. Nsight Compute — по желанию пользователя.
Варианты, которые сравниваются:
- **Отдельный конвейер «только луч»** (Jet7, без канала Якоби) — для фолбэка, этапа 4 и пролётов:
  он не платит регистрами за Якоби.
- **Якоби 4 поля в одном ядре** против **2×2 с повторным интегрированием** (тот же детерминированный путь
  дважды; вычисления в обмен на регистры).
- **Jet15** (1 + 4 + 10 симметричных компонент, произведение ≈ 45 FMA) против **HVP-jet**:
  J = a + b t + Σdᵢsᵢ + Σmᵢ t sᵢ (t² = 0, sᵢsⱼ = 0) — f, ∇f·w, ∇f, H·w за проход, 10 компонент, ≈ 27 FMA
  на произведение. Нужны H·v и H·J_k (k = 1..4): 5 проходов HVP против 1 прохода Jet15 — больше FMA,
  меньше живых регистров. S·J = P(H·J)/|∇f| для касательного J (M14).
  HVP сначала реализуется в прототипе и проверяется U1 против `jax.hessian` (произведения H·w).
- Отношение стоимости Jet15/скаляр с CPU-JAX (18–28×) **не переносится**: оно в основном из накладных
  расходов JAX. Стоимость меряется на GPU.

### 5. Wavefront
Очереди (буферы индексов лучей + счётчики на GPU):
1. **flight** — аналитический пролёт в плоских зонах (камера компактной червоточины → шар ρ₀; выход из шара →
   бесконечность). Поля Якоби переносятся через прямой участок: J ← J + t·J′, J′ без изменений (п. 7).
2. **integrate** — K шагов BS32 за диспетчеризацию, затем запись состояния. Завершившиеся лучи
   (выход / s_max / n_max) атомарно попадают в очередь «sample», активные — в очередь integrate следующей итерации
   (компакция: префикс-сумма по subgroup + один atomic на subgroup).
3. **sample** — выборка фона режима A (SampleGrad) или сохранение направления для детектора.
4. **detector** — отдельный проход по всему кадру (невязка M20 требует соседних центральных лучей).
5. **fallback** — N_fb лучей на помеченный пиксель через конвейер «только луч», накопление.
- Размер диспетчеризации — `vkCmdDispatchIndirect` из счётчиков на GPU. Хост не синхронизируется на каждой
  итерации: записывается фиксированное число итераций (с пустыми диспетчеризациями) и читается один счётчик
  в конце; повтор — только если очередь не опустела.
- **FSAL между диспетчеризациями не хранится**: в начале каждой диспетчеризации k1 вычисляется заново
  (+1 проход на K шагов). Это экономит 4 float4 (луч) или 20 float4 (с Якоби) на луч в памяти.
  K подбирается измерением (кандидаты 8, 16, 32, 64).

### 6. Раскладка данных и бюджет памяти (под 8 ГБ, как целевое железо из задания)
SoA-буферы, каждое поле — отдельный массив float4 / float / uint:
- луч: x, v (2 × float4), h, s (2 × float), статус + счётчики (uint), пиксель (uint) ≈ 48 Б;
- канал Якоби: J, J′ для 4 полей = 8 × float4 = 128 Б;
- итог для детектора/выборки: d∞ (float3), ∂d∞ по 4 полям (4 × float3), лист — ≈ 68 Б.

| | 1080p (2.07 М лучей) | 4K (8.29 М лучей) |
|---|---|---|
| луч + Якоби + итог (≈ 244 Б) | ≈ 0.51 ГБ | ≈ 2.0 ГБ |
| двойные буферы очередей (2 × 4 Б) | 17 МБ | 66 МБ |
| кубмапа 2 листа × 6 × 2048², BC6H с мипами | ≈ 64 МБ | ≈ 64 МБ |
| кубмапа RGBA16F (контроль) | ≈ 512 МБ | ≈ 512 МБ |

4K влезает в 8 ГБ с запасом. При нехватке — тайлы по 1–2 М лучей.

### 7. Производная направления выхода и перенос полей через пролёт
- Ручные формулы ∂d∞/∂(x, v) для Эллиса (дифференцирование M17 через sinc) и компактной червоточины
  (∂(v_q/|v_q|)). Сначала в прототипе, против существующих jvp-тестов (`test_exit_direction_derivatives`).
  Встроенное прямое AD Slang — альтернатива, если ручная формула окажется громоздкой.
- Перенос полей Якоби через аналитический пролёт: сначала прототип + тест против конечных разностей
  (камера компактной червоточины в плоской зоне), потом GPU. Без этого режим A на сцене 2 не работает.

### 8. Фон: кубмапы, BC6H, SampleGrad
- Мипы строятся из float32 (как в прототипе) **до** сжатия; затем BC6H (UFLOAT) по уровням. Контроль —
  RGBA16F без сжатия: ошибка BC6H измеряется отдельно от ошибки фильтра.
- Выборка куба в Vulkan бесшовная (`seamlessCubeMap` на десктопе всегда включён — проверить), поэтому рамку
  в 1 тексель из прототипа на GPU не делаем; эквивалентность подтвердить тестом по направлениям у рёбер.
- `SampleGrad(dir, ddx, ddy)` с анизотропией 16: ddx = k·σ₊·a₊, ddy = k·σ₋·a₋. Коэффициент k калибруется
  против `cubemap.sample_gauss_exact` на той же кубмапе (развёртка k ∈ [1, 4]) — критерий: максимум PSNR.
- Кодировщик BC6H — сторонняя зависимость, выбор за пользователем:

| кандидат | лицензия | как работает | плюсы / минусы |
|---|---|---|---|
| GPURealTimeBC6H (K. Narkowicz) | MIT | compute-шейдер HLSL, переносится в Slang | тот же GPU, без новых инструментов; качество «real-time» |
| AMD Compressonator | MIT | CLI / библиотека, CPU/GPU | высокое качество; тяжёлая зависимость |
| DirectXTex | MIT | CPU-кодировщик BC6H | эталонное качество; медленно, Windows-ориентирован |
| Intel ISPC Texture Compressor | MIT | CPU, нужен компилятор ISPC | быстро и качественно; новый инструмент в сборке |

  **Рекомендация:** GPURealTimeBC6H для рабочего пути + сравнение с RGBA16F; DirectXTex — только если
  ошибка BC6H окажется заметной на фоне ошибки фильтра.

### 9. Профилирование
- Время каждого прохода — timestamp queries (timestampPeriod = 1 нс), 1080p и 4K, медиана из ≥ 20 кадров.
- Счётчики на GPU: шаги и отказы на луч (гистограмма), доля лучей на фолбэке, число итераций wavefront.
- Регистры, спиллы, разделяемая память — `VK_KHR_pipeline_executable_properties`; занятость — расчёт.
- Nsight Compute / Graphics — если пользователь установит (для поиска узкого места, если 1080p ≫ 60 мс).

## Рассмотренные альтернативы и почему отвергнуты
- **CUDA C++** — нет тулкита; привязка к NVIDIA; генерики Slang удобнее для «SDF один раз».
- **GLSL / HLSL напрямую** — нет обобщённого программирования на пользовательских типах (в HLSL — только
  шаблоны в DXC 2021, без интерфейсов).
- **Мегаядро без очередей** — дивергенция между лучами с 30 и 2000 шагами; wavefront с компакцией лучше
  держит занятость (подтвердить измерением: мегаядро — первый, самый простой вариант для сравнения).
- **Встроенное AD Slang для всех производных** — нет контроля над числом регистров и временными; алгебра
  jet-чисел уже проверена U1.

## Бюджет производительности и памяти (оценка → позже измерение)
- Режим A, 1080p, Эллис: ≈ 100 вычислений правой части с Якоби на пиксель (этап 2: 102 прохода Jet15).
  Оценка ≈ 800 FLOP на вычисление (Jet15 Эллиса ≈ 400, правая часть Якоби ≈ 200, комбинации RK ≈ 160) ⇒
  ≈ 1.7·10¹¹ FLOP на кадр. Пик fp32 4080 SUPER ≈ 52 ТФЛОПС ⇒ ≈ 3 мс в идеале. С учётом дивергенции и занятости
  ожидание 15–40 мс — в ориентире 20–60 мс. **Это оценка; на 8-ГБ карте класса 4070 (≈ 29 ТФЛОПС) время выше
  примерно в 1.8 раза.**
- Память — таблица в п. 6.

## Итог реализации
(этап 3, отчёт: docs/reports/stage-3.md; цифры — `results/stage-3/2026-10-24_*`)
- **Язык и сборка (п. 1)** — по плану: Slang 2025.17.2 → SPIR-V → Vulkan, хост C++20 (volk, VMA), `gpu\build.cmd`.
  Генерики Slang выдержали полный код (11 SDF × Real/Jet7/JetHVP/Jet15/Dual4) без обходных путей. Шейдеры
  компилируются не на этапе сборки, а из Python (`geo4d.gpu.compile_shader`, кэш по хэшу исходника и define'ов);
  сцена выбирается define'ом, ветвления по сцене в ядре нет. Раскладка проще плановой: `scenes.slang`,
  `integrator.slang`, `trace.slang`, `modea.slang`, `wavefront.slang` вместо подкаталогов; `gpu/tools/` не понадобился
  (BC6H — шейдер `bc6h_core.slang`).
- **float32 (п. 2)** — правило применено: **κ = 3e-3**, α = 0.1/ℓ_s подтверждено (ADR-0004). Пол округления в
  1080p не достигнут; переписывать f Эллиса и вводить tol_min не пришлось.
- **Критерий п. 3** — пройден: e_GPU / e_прототип-f32 = 0.74–1.42 (лучи), 0.82–1.34 (Якоби), гиперплоскость 1.80
  при абсолютной ошибке ≤ 2e-6. При tol 1e-6 GPU уступает прототипу-f64 не в 10 раз, а в 2–7 — так же, как и
  прототип-f32, т. е. это округление float32, а не порт.
- **Регистры (п. 4)** — измерены через `VK_KHR_pipeline_executable_properties` (драйвер NVIDIA
  отдаёт число регистров). Интегрирование с Якоби: 252 регистра, занятость 17 %; «только луч» — 29–69.
  **HVP-jet не дал выигрыша** ни в регистрах (245), ни во времени — опция, по умолчанию Jet15. Вариант 2×2 не
  делался — остаётся первым кандидатом на ускорение интегрирования.
- **Wavefront (п. 5)** — сделан графом задач в хосте (`geo4d_gpu graph`: косвенные диспетчеризации, циклы, метки
  времени, весь кадр — один командный буфер). Интегрирование не ускорилось относительно мегаядра (длины лучей
  компактны, предел — занятость); выигрыш — во фолбэке порциями по 8 сэмплов (43.7 → 27.3 мс). Лучший K = 32.
  Число итераций — из калибровочного прогона (+2) вместо фиксированного запаса.
- **Память (п. 6)** — SoA по плану; 4K помещается без тайлов.
- **Пролёт и производная выхода (п. 7)** — ручные формулы заменены дуальными числами (Dual4, M24), перенос полей

- **Фон (п. 8)** — кубмапа без рамки (бесшовная выборка Vulkan); отдельный тест по направлениям у рёбер
