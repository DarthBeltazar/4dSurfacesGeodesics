# 2026-10-24-07: окна на других ОС и запуск из IDE (ADR-0008)

Запрос пользователя: «конфигурации, чтобы было удобно запускать сцены из IDE, поддержку окон на других os».

## Сделано
- **Хост.** Внешняя память по платформе (Win32 HANDLE / Linux fd → `CU_EXTERNAL_MEMORY_HANDLE_TYPE_OPAQUE_FD`),
  `dlopen("libcuda.so.1")`, MoltenVK portability.
  - Обязательные возможности устройства проверяются с понятной ошибкой; `subgroupSizeControl` включается, только
    если поддерживается.
  - Денойзер необязателен в рантайме, `buffer X export` без внешней памяти даёт обычный буфер.
  - `GEO4D_APP` и `GEO4D_OPTIX` — независимые опции; `app.cpp` собирается без OptiX.
- **Сборка.** Корневой `CMakeLists.txt` + `CMakePresets.json`; `build.cmd` конфигурирует корень через пресет;
  `build.sh`. Если SDK нет, зависимости приходят из FetchContent. В Python — `GEO4D_GPU_EXE` и `GEO4D_SLANGC`.
- **IDE.** `.run/` (13 конфигураций) генерирует `prototype/scripts/ide_configs.py`; `app.py --graph-only` нужен для
  запуска хоста под отладчиком.

## Проверки
- **Windows:** `pytest -m gpu` — 32 passed, без пропусков (включая `test_gpu_app`: обмен памятью с CUDA побитово
  равен копиям).
- **Linux, WSL2 Ubuntu 26.04, gcc 15:** сборка со всеми зависимостями из FetchContent. Приложение на lavapipe в окне X11
  (WSLg): переход на нижний лист, накопление 11, swapchain побитово равен выводу; денойзер отключился штатно
  (`results/stage-5/2026-10-24_linux_wsl_smoke`). Запуск — обёртка, переписывающая пути графа на `/mnt/c`.
- GPU-тесты `run`/`graph` (без денойзера и приложения) против Linux-бинарника на lavapipe: **30 passed** за 10.5 мин, без пропусков (`…_linux_wsl_smoke/pytest_gpu_lavapipe.txt`). Сверки GPU с прототипом проходят и на CPU-растеризаторе Mesa.
- **Linux нативно:** свежий клон в WSL, `./gpu/build.sh` (пресет, Unix Makefiles, бинарник `gpu/build/geo4d_gpu`), venv
  Python 3.14, Linux-`slangc` 2025.17.2; `app.py --bench` на lavapipe — swapchain побитово равен выводу
  (`results/stage-5/2026-10-24_linux_native_app_bench`). Python-путь Windows-специфики не содержит (`nvidia-smi` в
  `meta()` в try).
- **CLion:** все 13 конфигураций загрузились (`get_run_configurations`). Python-конфигурации не запустились: в CLion
  не зарегистрирован интерпретатор («Cannot find Python interpreter») — пользователь должен один раз добавить `.venv`
  (README). После того как CLion перечитал CMake, конфигурация «geo4d_gpu info» собрала цель профилем Debug и запустилась (exit 0, RTX 4080 SUPER). CLion при этом вписал в файлы `.run` имя своего локального профиля (`CONFIG_NAME="Debug"`) и убрал предзапуск Python-конфигурации, пока интерпретатор не зарегистрирован. Изменения откачены; такие правки IDE не коммитить.

## Что не получилось и почему
- **OptiX в WSL:** `libnvoptix.so.1` — заглушка dxcore без `optixQueryFunctionTable` (`OPTIX_ERROR_ENTRY_SYMBOL_NOT_FOUND`
  даже с `LD_LIBRARY_PATH=/usr/lib/wsl/lib`). CUDA (`cuInit`) при этом работает. Импорт fd на нативном Linux с NVIDIA
  не проверен.
- **SDL `offscreen` на lavapipe:** `vkCreateSwapchainKHR` → `VK_ERROR_OUT_OF_DEVICE_MEMORY`. Для окна не нужен.
- **`SDL3Config.cmake` из Vulkan SDK 1.4.328** ссылается на `Lib/cmake/lib/SDL3.lib` (неверный префикс). Цель
  задаётся вручную из `Lib/SDL3.lib` + `Bin/SDL3.dll`.
- **SDL с заголовками X11 из `dpkg-deb -x`:** dev-симлинки `.so` указывали в никуда, и линковка шла со статическим
  `libX11.a` без xcb. Тогда проверка XGenericEvent падала и SDL ломался на `XGenericEventCookie`. Симлинки
  перенаправлены на системные библиотеки.
- **Патчи через heredoc снова съели `\n`** в строках C++/Python (три раза). Такие правки — только через Edit.
- `build.sh` закоммичен без бита исполнения (`git update-index --chmod` до `git add` не сработал) — исправлено.
- В venv дистрибутивного Python нет `ensurepip` — pip через `get-pip.py` (только для проверки).
- macOS не проверен: нет машины. Исправлено вслепую: расширение portability не добавляется второй раз, если его уже
  вернул SDL.
