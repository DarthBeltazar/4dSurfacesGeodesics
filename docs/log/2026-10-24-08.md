# 2026-10-24-08: GUI и быстрое редактирование сцен (DD-008)

Запрос пользователя: «добавить GUI и возможность быстрого редактирования сцен». Выбор пользователя (вопрос в начале
сессии): **Dear ImGui в окне**; объекты — мгновенно, многообразие — из GUI с перекомпиляцией на лету.

## Сделано
- **Объекты в буфере GPU.** `pt_scene.slang` содержит только плоские зоны и `PT_MAXOBJ = 32`; объекты, материалы и
  список NEE-источников — строки float4 в хвосте буфера камеры (`gCam[8…]`, `gpu_pt.object_rows`). Буфер камеры уже
  привязан на binding 0 во всех конвейерах (и в `cam_step`), так что привязки не менялись. `obj_g` — `switch` по виду.
- **M34** (`pathtrace.nee_lights`, `editor.cpp::nee_lights`): источник NEE — только целиком в плоской зоне на листе;
  на сценах этапа 4 совпадает с ручными списками.
- **Параметры многообразий** — дефайны `scenes.slang` (`MF_*`, по умолчанию — прежние константы; hcap компактных
  червоточин теперь `0.25·b`, как в прототипе). `gpu_pt.manifold_defines` из `Shape.params`.
- **Файлы сцен** `scenes/*.json` (`geo4d.scenefile`): все сцены окна + `hyperplane`; `app.py --scene` — имя или путь.
- **Хост:** ImGui v1.91.9b (FetchContent), бэкенды SDL3 + Vulkan через volk, dynamic rendering поверх скопированного
  кадра; панели «Сцена» (рендер, многообразие, файл) и «Объекты». Правка → упаковка строк в C++ → запись в буфер →
  секция `edit` (класс пикселей и режим A заново, без шага камеры) → сброс накопления. «На M» — ядро `pt_snap`.
  Смена многообразия — JSON с текущей камерой → `app.py --graph-only` в фоновом потоке → новый `GraphProgram`,
  повторный импорт буферов денойзера; ошибка Python — сообщение в окне, сцена прежняя.
- **Зерно ГСЧ** в окне при неподвижной камере — по номеру сэмпла накопления (раньше — по номеру кадра), чтобы
  правка была побитово равна холодному старту.
- Директивы для проверок: `edit <кадр> <строки.npy>`, `remanifold <кадр> <вид> k=v…`, `ui` (оверлей в сценарии —
  снимок окна с панелями).

## Что не получилось и почему
- Тест «GPU против прототипа» на изменённом Эллисе с **постоянным** фоном упал: пиксели без объектов имеют нулевую
  дисперсию, и float32-округление фона (0.99999 против 1) засчитывалось выбросом. Взят процедурный фон, как в тесте
  этапа 4.
- Тот же тест на изменённой сцене 3: 2 выброса > 4σ из 36 пикселей (лимит 5 % < 2). Пиксель 9: z = 12.5 при 256 spp
  прототипа (0.374 ± 0.018 против 0.553 у GPU), у соседей σ ≈ 0.2 — тяжёлые хвосты. Перепроверка: прототип 2048 spp,
  другое зерно — 0.613 против 0.546, z ≈ 1 (смещения нет). Лимит выбросов в новом тесте — 10 %, spp прототипа — 512.
- Источник, добавленный в тесте горячей правки в (2, 2, 1), не стал NEE-источником — правильно: шар задевает зону
  кривизны горловины c₂ (расстояние 3 < ρ₀ + r). Источник перенесён.
- Замер при `app.py --bench` перезаписал закоммиченные каталоги результатов (та же дата и имя) — откачены;
  добавлен `--tag` для суффикса каталога.
- Патчи через heredoc снова съели `\n` в строках (Python и C++) — исправлено через Edit.
- Интерактивный ввод (клики, перетаскивание полей) автоматически не проверен: нет доступа к экрану; путь кода тот же,
  что у директив `edit`/`remanifold`, кроме самих виджетов ImGui.
